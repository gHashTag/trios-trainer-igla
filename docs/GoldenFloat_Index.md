## The design rule (one sentence)

> GoldenFloat is the only published floating-point family whose
> exponent:mantissa split, at **every** bit width on a 4-to-256-bit ladder, is
> generated by one closed rule — **E/M → 1/φ** — anchored in a single algebraic
> identity, **φ² + φ⁻² = 3** (1/φ = 0.618034…).

Two structural properties make the family more than a naming scheme:

- **Integer-backed.** Every member is stored in a plain unsigned integer
  (`u8/u16/u32/u64`) — **no hardware half-type dependency**. It runs on any
  integer ALU (CPU, MCU, FPGA, WASM, LLVM IR), sidestepping the f16
  compiler-ecosystem fragmentation.
- **Lucas-closure-safe accumulators.** φ²ⁿ + φ⁻²ⁿ is always an integer (a Lucas
  number), so φ-scaled sums stay **exact** in integer storage.

## 2. The float ladder — verified constants (R5)

Bit budgets, the `BIAS = 2^(E−1)−1` formula, and the φ-distances below were
**independently re-derived** and are VERIFIED (the GF256 stored bias excepted —
see §6).

| Format | S+E+M | Bits | BIAS = 2^(E−1)−1 | EXP_MAX = 2^E−1 | E/M | φ-distance |E/M−1/φ| | t27 spec |
|---|---|---|---|---|---|---|---|---|
| GF4 | 1+1+2 | 4 | 0 | 1 | 0.500 | 0.118 | `gf4.t27` |
| GF8 | 1+3+4 | 8 | 3 | 7 | 0.750 | 0.132 | `gf8.t27` |
| GF12 | 1+4+7 | 12 | 7 | 15 | 0.571 | 0.047 | `gf12.t27` |
| GF16 | 1+6+9 | 16 | 31 | 63 | 0.667 | 0.049 | `gf16.t27` |
| GF20 | 1+7+12 | 20 | 63 | 127 | 0.583 | 0.035 | `gf20.t27` |
| GF24 | 1+9+14 | 24 | 255 | 511 | 0.643 | 0.025 | `gf24.t27` |
| GF32 | 1+12+19 | 32 | 2047 | 4095 | 0.632 | 0.014 | `gf32.t27` |
| GF64 | 1+24+39 | 64 | 8388607 | 16777215 | 0.615 | 0.003 | `gf64.t27` |
| GF256 | 1+97+158 | 256 | 2⁹⁶−1 | 2⁹⁷−1 | 0.614 | 0.004 | `gf256.t27` (γ) |

By φ-distance the closest split to 1/φ is **GF64 (0.003)**, then **GF256
(0.004)** and **GF32 (0.014)**; GF12 (0.047) is the best only among formats
≤ 16 bits.

## 3. PHI_BIAS — empirical per format (NOT a closed-form law)

PHI_BIAS is the per-format mantissa-rounding bias used when quantising from
higher precision. The earlier closed form `PHI_BIAS = EXP_MAX − BIAS` is
**RETRACTED** (it reproduces only GF64). No single formula reproduces all eight
values, so each is defined empirically ("H_E") and held in its `gfN.t27` spec.

| Format | PHI_BIAS | Status |
|---|---|---|
| GF4 | 0 | EMPIRICAL FIT (minimal for 4-bit) |
| GF8 | 1 | EMPIRICAL FIT (minimal; coincides with L₁ = 1²) |
| GF12 | 2 | EMPIRICAL FIT |
| GF16 | 60 | NORMATIVE (production; 2·BIAS−2 = 2⁶−4) |
| GF20 | 289 | EMPIRICAL FIT (coincides with 17²) |
| GF24 | 1364 | EMPIRICAL FIT (coincides with Lucas L₁₅) |
| GF32 | 0 | EMPIRICAL FIT (minimises MSE vs round-to-nearest-even) |
| GF64 | 8388608 | EMPIRICAL FIT (equals EXP_MAX − BIAS for this format only) |

The Fibonacci/Lucas/perfect-square coincidences (GF24 = L₁₅, GF20 = 17²) are
**descriptive, not prescriptive** — they must not be used to generate PHI_BIAS
for new formats.

## 4. Implementation status (claim discipline)

- **GF16 — VERIFIED.** Production Rust (`trios-trainer-igla`) plus C codegen;
  the one format used in the live training pipeline.
- **GF32 — CLAIMED IN SOURCE, NOT INDEPENDENTLY CONFIRMED.** At least three
  incompatible bit-layouts exist (12/19, 13/18, and an IEEE-fp32-identical
  variant); see the Unified Specification Audit chapter.
- **GF4 / GF8 / GF12 / GF20 / GF24 — ROADMAP.** Spec extract-only with C codegen
  present; no Rust implementation yet.
- **GF64 — ROADMAP.** PHI_BIAS defined in spec; C codegen still missing.
- **GF236 — does not exist.** `236` is the *mantissa width* of IEEE binary256
  (1 + 19 + 236 = 256), not a format. The canonical 256-bit GoldenFloat is
  **GF256**; there is no GF236.

## 5. The ternary members (TF3 ≠ GFTernary)

Two distinct objects, often conflated:

- **TF3** (`tf3.t27`) — a real **8-bit** format, layout **1:3:4** (the same
  geometry as GF8), used to encode ternary neural-network weights. It is a
  storage container, **not** a 2-bit format.
- **GFTernary** — the conceptual **2-bit** limit case, values in {−φ, 0, +φ},
  φ-distance **0.000** by construction. The bulk-quantisation idea behind the
  hybrid *ternary + GF16* architecture and the {−1, 0, +1} substrate of the
  Three Crowns. Marked "concept only" (no normative spec); ships as ROADMAP.

## 6. The "GF" name collision — field vs float

"GF" denotes both **G**alois **F**ield and **G**olden**F**loat. Never conflate
them in a publication.

### GF16
- **GF16-Float** — the 16-bit GoldenFloat (1:6:9), §2 above. A real-number type.
- **GF(2⁴)** — the 16-element Galois field of the Euler crown. A finite field
  for XOR/LUT arithmetic, not real numbers.

### GF256 — three distinct things

| Kind | Locus | What it is | Layout / polynomial | Status |
|---|---|---|---|---|
| GF(2⁸) field | `trinity/specs/crypto/gf256.tri` | Galois field 𝔽₂₅₆ for crypto / erasure coding | primitive poly `0x11D` (285) — **not** the AES `0x11B` | Implemented (Zig) |
| GF256 float (γ-ratio) | `tt-trinity-gamma/specs/fpga/gf256.t27` | 256-bit φ-ratio float | S:1 E:97 M:158; E/M 0.614; φ-dist 0.004 | FPGA spec / RTL gen |
| GF256 float (range) | `zig-golden-float` whitepaper | proposed binary256-*range* φ float | range-matched (~19 exp bits) | Candidate only |

**R5 flag (GF256 float, γ-ratio):** the spec's stored exponent-bias constant
(≈ 2⁷¹) does **not** match `2^(E−1)−1 = 2⁹⁶−1`; the bias is treated as **OPEN**
until reconciled. Only its geometry (97/158 split, φ-distance 0.004) is
verified.

## 7. Candidate formats (proposed, no normative spec)

- **GF6** — φ-gap fill between GF4 and GF8 (FP6 E2M3 hint: φ-distance ≈ 0.05).
- **GF128** — binary128-range φ candidate (paired with the GF256 range variant).

## 8. Measured comparison (IGLA RACE v2, frozen 2026-05-25)

Validation bits-per-byte (lower = better) for the same byte-level LM trained
under each numeric format (2–3 seeds; `fp8_e4m3` died pre-eval → NO_EVAL):

| Format | Mean val_bpb | Reading |
|---|---|---|
| f32 | 2.5414 | full-precision baseline |
| fp16 | 2.5501 | best 16-bit in this sweep |
| **gf16** | **2.5725** | +0.031 bpb vs f32; **beats bf16** |
| bf16 | 2.6135 | worst of the 16-bit group |
| posit8 | 2.9322 | best 8-bit in this sweep |
| **gf8** | **2.9322** | **bit-identical to posit8** |
| int8 | 3.4189 | linear 8-bit, well behind |
| mxfp8 | 3.4677 | ≈ int8 |
| fp8_e5m2 | 3.8528 | range-biased FP8, degrading |
| nf4 | 3.9985 | 4-bit, at the edge |
| int4 | 7.0184 | does not learn |

**Honest reading:** GF16 is parity-class with fp16 and a measured win over
bf16 — *not* the single best 16-bit format (fp16 edges it). GF8 ties posit8
exactly. No GF-vs-E4M3 head-to-head exists. NF4/E5M2 underperform here because
this is from-scratch training, not post-training weight-quant. A *bounded*
empirical result, not a universal optimum.
